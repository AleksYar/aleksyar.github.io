TSP20: progress is clear; a paired baseline is still needed

Our latest run produced 90 valid tours out of 100, with 2.35% mean gap on valid tours. It solved 20/100 optimally and 41/100 within 1%. All 100 answers were independently rescored.

Checkpoint access is blocked. The authors shared checkpoints in GitHub issues, but their OneDrive folder currently says “Sorry, the link has expired.” The preparation below contains no LLMCoSolver model outputs and no GPU job has been submitted.

Paper results: Table 1 and Table 2. The latter groups 10–30 cities and reports 96% within 1%; it is not a separate TSP20 result. The full method includes RL and best-of-8. Training uses 500k mixed-size examples, versus our 100k TSP20 examples. The authors report their best of three runs on H100 hardware.

Interpretation. Our one-answer SFT result is numerically close to their SFT result. Different datasets, model architectures, training budgets and inference methods prevent a parity claim. On our own cases, nearest neighbor plus 2-opt currently gives better gap and reliability. The validation set was inspected during training and is not a fresh final test.

What the local run establishes

LLaDA-8B-Instruct, BF16 LoRA rank 16 / alpha 32, one epoch, 100,000 examples, one L40S, 128 diffusion passes over 512 output slots, one answer per case. Mean generation time was 22.84 seconds. Prompts already include the two nearest neighbors, as in the authors’ approach. Distances are recomputed from coordinates; none of the 90 valid tours had a correctly reported objective to three decimals.

Prepared test

  1. Obtain an accessible TSP adapter/checkpoint. Verify its base model and whether it is SFT or SFT+RL. Issue #2 reports a Llama adapter despite the Qwen default. Issue #6 confirms SFT checkpoints for CVRP, not TSP.
  2. Evaluate one greedy answer on the same 100 TSP20 geometries, with native prompt wrappers and the same neighbor information. Use full-precision exact references and strict tour validation. Keep all answers and timing.
  3. Evaluate best-of-8 as a separate experiment; select by recomputed length among strictly valid tours. The repository defaults to top-p 0.9 while the paper states 0.7; freeze the choice.
  4. Run a new disjoint TSP20 test once settings are fixed. A matched-data Qwen SFT run on our existing 100k examples is also useful, but would be a new controlled baseline, not a reproduction of the published training.

Scoring audit

Replaying the authors’ scorer on our 100 saved answers gives 90% validity and 2.350158% gap, consistent with our result up to reference rounding. An isolated regression example shows that their scorer accepts an extra revisit because it checks distinct-city count rather than exact route length. Our strict scorer rejects it. This code finding does not establish that their reported results contain such tours.
