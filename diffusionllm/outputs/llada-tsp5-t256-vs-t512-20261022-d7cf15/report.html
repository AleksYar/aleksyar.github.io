Does a larger output budget help?

The same 20 five-city problems and unchanged coordinates-only prompts, run in parallel on two A40 GPUs. Each job uses one GPU, 128 diffusion steps, and a 15-minute limit.

More output space improved tour completeness in this pilot.

Complete tours, ignoring missing brackets: 11/20 at 256 tokens and 16/20 at 512 tokens. 6/20 readable answers are identical between the two settings.

256 tokens
11/20
512 tokens

What changed: output length is 256 versus 512 positions. Each setting keeps one diffusion block covering the entire output, so block length changes with output length. With 128 steps, the sampler reveals 2 versus 4 positions per step. This is a comparison of output budgets at fixed step count, not a test with more diffusion steps or a request for a longer explanation.

Scoring: the primary benchmark retains the original bracket parser. A separate diagnostic accepts an unambiguous bare comma-separated route without adding, removing, or reordering city IDs. A complete TSP5 tour must contain every city once and return to its start. Gap is undefined for incomplete tours. The average gaps above use each arm’s complete subset, which may differ.

On the 11 instances complete under both settings, mean gaps are 11.55% (256) and 11.55% (512). Comparing the same cases: 11 stayed complete; 5 became complete; 4 stayed invalid; 0 became invalid.

Did the answers actually get longer?

Visible token counts measure the readable answer before the first end token. The full 256- or 512-position canvas is saved separately, including end tokens and any content after them. A larger canvas does not require the model to use more readable tokens. The prompt still requests one route and no explanation.

Every complete answer in both settings uses the same city order: [0, 1, 2, 3, 4, 0]. Improved completeness therefore does not demonstrate that route order adapts to the coordinates.

The additional visible tokens at 512 come from spaces after commas. All answers contain the same number of city IDs and no explanation. Two numerical route patterns account for every answer; the four readable variants at 512 reflect spacing differences.

Reproducibility and limits

The 256-token control reproduces 20/20 prior readable answers and 20/20 full token arrays. Model, dataset, source, and configuration hashes were verified. Slurm confirms both jobs completed successfully, with 260 seconds of overlapping execution. The elapsed interval from the first job start to the last finish is 404 seconds; this excludes preparation and queue time.

This is a small development pilot, reused to explore decoding choices. It does not establish an unbiased final benchmark or show how performance generalizes to larger TSP instances. Neither model was fine-tuned. Both use BF16, temperature 0, seed 42, no adapter, and the pinned official sampler.
